# Ferry 多 AI、多分支并行开发方案

shizichen，建议采用“统一协议先冻结、平台适配并行、集成分支持续验收”的 14 个开发职责分支方案。

## 关键点

1. 先定义迁移承诺：归档可读、交接续聊、原生续聊分别验收，不承诺任意平台之间无损恢复运行现场。
2. 用现有 UCM、Store/Importer 协议和 Node.js 本地架构增量开发，不另起微服务、插件市场或新技术栈。
3. 14 个是职责分支，不是必须同时运行 14 个 AI；建议从 4 个 AI、独立 worktree、分波次领任务开始。
4. 平台负责人交付自己的代码、脱敏样本、单元测试和能力证据；集成人独占注册表、依赖清单和发布入口。
5. 原生导入必须通过版本探测、预演、备份、受控写入、验证和回滚；未通过的功能保持只读或交接模式。

## 展开

### 1. 现状、假设与置信度

- 方案日期：2026-10-19。仓库已有 Ferry 原型，包含 `src/core/`、`src/adapters/`、`src/ui/` 和 CLI，不需要重建项目。
- Git 盘点显示当前稳定分支名称为 `master`，尚无首次提交，现有实现处于未跟踪状态。先由维护者确认需要纳入版本控制的文件并建立基线，不直接执行 `git add .`。
- 本次仅检查原型和格式文档，没有运行测试、登录平台或执行续聊验收。README 的支持声明不等于本方案的验证证据。
- OpenAI 官方文档访问返回 HTTP 403，其他厂商能力本次也未逐一核验。平台接入方式属于实施假设，不是当前能力认证。
- 架构与分支隔离方案置信度高；具体平台、版本、账号套餐是否允许导出和原生回写，必须实测。
- 默认 Copilot 指 GitHub Copilot Chat；Microsoft Copilot 需要单独任务。Claude 网页与 Claude Code、通义网页与 Qwen Code 也分别建模。

### 2. 明确“迁移后继续使用”的含义

| 模式 | 用户得到什么 | 验收与限制 |
|---|---|---|
| 同产品、同账号换电脑 | 通过产品自身同步继续原会话 | 优先验证官方同步是否已满足需求，不搬运云端数据库 |
| 归档迁移 | 在另一电脑查看、检索可导出的历史 | 校验消息、顺序、分支、可获得附件及来源，显示缺失项 |
| 交接续聊 | 把上下文交给另一模型或应用，在新会话中继续 | 不是恢复原会话，受上下文窗口、模型和附件能力限制 |
| 原生续聊 | 会话出现在目标历史列表，可发下一条消息，重启后仍在 | 只对经过验证的来源到目标、版本和 OS 组合开放，格式损失必须披露 |
| 运行现场恢复 | 终端、进程、内存、MCP、远程文件、登录授权一起恢复 | 不属于历史对话迁移 MVP，不作承诺 |

云端产品没有经过验证的官方写入接口时，只交付归档、交接包或同账号同步指引。模型 API 能接收历史上下文，不等于能把历史写进消费者聊天产品的会话列表。默认不采集 Cookie、不搬运登录令牌、不绕过账号或组织边界、不用私有接口注入历史。

项目代码、依赖环境和工具服务不随对话自动恢复。记录路径、Git commit、依赖提示和工具名称，提供预检；目标电脑另行准备代码并重新授权。只保留源数据实际提供且允许导出的内容，不声称恢复隐藏推理或未落盘状态。

### 3. 架构与划分依据

保留 Node.js ESM、CLI 和本地 Web UI，使用单仓库、单进程本地架构。先复用现有实现；确有安全或格式解析需求时评估成熟依赖，不为“零依赖”牺牲安全。

```text
源文件 / 用户授权的本地存储
  -> 平台读取适配器
  -> UCM + 附件仓库 + 来源与缺失记录
  -> .ferrypack / JSON / Markdown / 交接包
  -> 导入预检与损失报告
  -> 目标适配器生成 ImportPlan
  -> 核心执行备份、受控写入、索引更新、验证
  -> 原生续聊入口 / 交接包 / 回滚入口
```

- 按变化来源拆分：平台格式归适配器，迁移事务归核心，编码与容器归格式转换，交互归 GUI。
- 按文件所有权隔离：每个可写文件只有一个分支负责人，避免多个 AI 同改公共大文件。
- 按依赖方向限制：适配器依赖协议，不依赖其他适配器、GUI 或 CLI；GUI 调核心，不复制迁移逻辑。
- 按安全边界集中：平台模块理解格式并构造写入计划，不能自行绕过核心写入控制。
- 新增平台只加读取器或目标计划生成器，不建设每对平台一套转换器；实际兼容性仍逐组合验收。

### 4. 前置分支：冻结最小契约

`feat/contracts-v1` 是唯一技术前置分支。先交可运行的小契约与固定样本再并行，不先建设大型 SDK。

**必须冻结的内容**

- UCM：会话/消息 ID、角色、时间、父节点/分支、当前分支、内容块、工具关联、附件引用、项目元数据、来源产品/格式版本及未知字段保留规则。
- 身份：产品 + 来源作用域 + 原 session ID；内容哈希/revision 区分版本，标题不能作唯一键。来源作用域优先用隐私化稳定标识，无法取得账号范围时由导出源分配并保留 namespace，不写入凭据。
- 存储适配器沿用 `scan(env)`、`read(env, ref, ctx)`；文件导入器沿用 `detect(buf, filename)`、`read(buf, filename)`。已验证可写目标新增 `planImport(...)`。
- ImportPlan：目标产品/格式版本、允许写入根目录、文件及索引/DB 变更、资源锁、旧状态摘要、ID 映射、损失列表和续聊入口；生成计划必须零写盘。
- 核心入口：导出收集、包读写、`planImport`、`applyImportPlan`、`rollback`，统一进度、取消、错误和结果结构。这是拟议契约，不表示当前已全部实现。
- 能力声明：未验证、fixture 通过、真实导出通过、真实原生续聊通过分别记录，附 OS、来源/目标版本、格式签名、验证日期和证据。
- 损失报告：逐项列出丢失、降级、截断、无法恢复的附件/工具/分支，未知损失也报告，不能把解析成功当无损。
- golden fixtures 和 mock：文本、工具关联、附件、分支、损坏输入，使平台、GUI、测试不等待核心实现。

**针对当前代码，先拆必要的冲突热点**

1. `src/adapters/web-exports.js` 混合 ChatGPT、Claude 和通用格式，前置分支将其拆成独立文件，原入口暂保留兼容 re-export。
2. `src/core/ucm.js` 混合模型、渲染、交接与脱敏，先把后三者搬入独立文件并保留兼容导出；冻结后 UCM 本体仅归契约负责人。
3. 平台测试移入独有目录，公共测试工具单独定负责人，避免所有人改两个大测试文件。
4. 集成人一次更新测试发现规则和注册规范；现有适配器保留，不因拆分覆盖既有实现。
5. 当前 `importScope` 的平台专用备份范围由核心负责人逐步改为目标计划声明，新平台不再要求各人改核心 switch。
6. 旧适配器也必须符合安全门禁；不能完整声明写入范围的原生写入暂关闭，保留只读。只拆协作必需部分，不开展无关重构。

### 5. 14 个开发职责分支

下表 C 表示契约基线，M 表示迁移核心，P 表示归档转换。实现依赖可到联调时才满足，开发阶段依赖 C 的 mock，禁止直接引用别人未合并的工作目录。

| 分支 | 职责 / 独占文件 | 交付物 | 依赖 / 禁区 |
|---|---|---|---|
| `feat/contracts-v1` | `src/core/adapter.js`、UCM 本体、契约文档、首次必要拆分 | schema、接口、固定样本、mock、契约版本标签 | 最先合入；各平台不能私改公共协议 |
| `feat/migration-engine` | migrate、backup、sqlite、env、路径/受控写入模块、`src/cli.js` | 导出编排、预检/预演、稳定 ID、冲突策略、操作日志、中断恢复、回滚、CLI | C；联调需 P 和目标适配器；不写平台解析 |
| `feat/package-conversion` | archive、tar/zip/crypto、拆出的渲染/交接/脱敏模块、通用 JSON/Markdown 适配器 | .ferrypack、哈希验证、认证加密、Blob 去重、通用转换、上下文预算/损失报告 | C；不回写目标存储或修改平台解析器 |
| `feat/adapter-chatgpt` | 独立 ChatGPT 解析文件、专属测试/样本/文档 | 用户提供导出包的探测/解析、对话树、主分支、多模态引用、ID/时间、缺失报告 | C + P 的安全归档接口；不承诺写回 ChatGPT 账号 |
| `feat/adapter-claude-web` | Claude 网页解析文件、专属测试/样本/文档 | 经样本验证的导出解析、消息块/附件可用性、能力证据 | C + P；不改 Claude Code，不默认支持云端账号导入 |
| `feat/adapter-claude-code` | `src/adapters/claude-code.js`、专属测试/样本/文档 | 扫描/读取、版本探测、目标计划、项目映射、索引与续聊证据 | C；原生联调需 M；不直接执行写入 |
| `feat/adapter-cursor` | `src/adapters/cursor.js`、专属测试/样本/文档 | 明确版本的存储读取、ID/索引关联、目标计划、真实重启续聊记录 | C；原生联调需 M；未知 schema 只读，不猜测字段或复制凭据 |
| `feat/adapter-copilot` | `src/adapters/vscode-copilot.js`、专属测试/样本/文档 | 明确 VS Code/扩展版本的读取、工作区关联、可支持的目标计划 | C；原生联调需 M；仅 GitHub Copilot Chat，不包括 Microsoft Copilot |
| `feat/adapter-qwen` | 通义网页独立适配文件、专属测试/样本/文档 | 能力探测；有授权可得格式就解析，否则交人工导出/通用接入及限制 | C；通义网页不等于现有 Qwen Code 支持，不伪造官方导出能力 |
| `feat/adapter-wenxin` | 文心独立适配文件、专属测试/样本/文档 | 产品/账号/格式调查、可实现的只读解析、数据获取与降级报告 | C；没有合法稳定入口就交能力报告，不开发空壳接口 |
| `feat/adapter-deepseek` | DeepSeek 网页独立适配文件、专属测试/样本/文档 | 经样本确认的文件/文本解析、来源元数据、交接能力和限制 | C；网页与模型 API 分开标识，无已验证接口不做云端回写 |
| `feat/gui` | `src/ui/`、`src/server.js`、GUI 专用测试 | 扫描/选择、导出、预览、路径映射、损失确认、进度/取消、结果/回滚、本地 API 安全 | C 的 mock 即可开工；联调需 M/P/适配器；不改核心 |
| `test/compat-e2e` | 契约/跨模块/E2E/安全测试、公共测试工具 | 跨 OS/版本矩阵、故障注入、回滚/重入/隐私测试、真实续聊清单 | C；先写黑盒预期，随模块到货联调；不替作者写全部单元测试或修业务代码 |
| `chore/integration-release` | 注册表及别名公共部分、package/锁文件、CI、打包脚本、README、发布矩阵 | 合并队列、平台注册、依赖协调、打包/冒烟、版本与能力矩阵、回退说明 | C 后可建设；发行需 M/P 和本轮已验收平台，不等待全部平台 |

每分支同时拥有自己的模块单元测试、fixture 和专属文档，例如 `test/adapters/chatgpt/`、`docs/platforms/chatgpt.md`。公共工具单一负责人。现有 Codex 等适配器需要扩展时，另开同规则小分支，不凭 README 跳过验收。

平台探测任务限时进行。没有合法稳定入口时，交调查证据、通用文件接入路径及明确“不支持”状态即可结束该阶段，后续能力开放再开 PR，不阻塞版本。

### 6. 依赖图

```text
已确认的首次提交 -> contracts-v1 -> integration 契约基线 C
                                      |
                                      +-- M: migration-engine --+ 安全写入/CLI
                                      +-- P: package-conversion + 归档/交接
                                      +-- 各平台适配器 ---------+ 读取/目标计划
                                      +-- GUI（先用 mock） -----+ 用户流程
                                      +-- 契约/E2E 测试 --------+ 验收
                                      +-- 集成发布基础 ---------+ 持续合并
                                                               |
                                   首条可用链路 -> 小版本 -> 扩展平台
```

临界路径通常是“契约 -> 最小核心/包格式 -> 一个来源和目标 -> 两机验收”，不是所有平台完成。GUI、平台解析、黑盒用例可同时推进；真实产品续聊不能由 mock 替代。

### 7. Git 合并策略

分支流向为 `master <- integration <- feat/* / test/* / chore/*`。`master` 是本仓库实查名称；未来若改名，以真实稳定分支为准。integration 是长期集成线，不计入上述 14 个职责分支。所有拟议分支/标签本次均未创建。

1. 维护者确认未跟踪文件、忽略规则、隐私与基线，完成首次提交，再建立 integration。保留用户未提交改动，不做全量自动纳入。
2. 契约 PR 合入 integration，标记 `ferry-contract-v1`。所有功能从包含此契约的 integration 提交起分支，每 AI 一个独立 worktree，每分支一名写入负责人。
3. 尽早交小 PR，按读取、计划、真实续聊分阶段交付；测试通过到哪一级才声明哪一级能力。平台 PR 附注册说明，注册由集成人串行完成。
4. PR 经过非作者评审、文件边界检查、契约测试和合并队列；队列验证“拟合并结果”，不是仅验证旧分支 HEAD。
5. 建议任务 PR squash 到 integration，保持回退边界清楚；integration 到 master 使用正常 merge 或 `--no-ff` 保留里程碑关系。共享分支不 rebase、不强推。
6. 功能分支用 merge 更新最新 integration 并重测。公共契约必须变动时，先独立契约 PR，再通知消费者、同步 mock 和契约测试。
7. 失败集成用可追溯 revert 或关闭实验写入，不 reset/强推。每日滚动接收已验收小 PR，不到最后一天集中合并。
8. 发布后同步稳定线与集成线；稳定线紧急修复需回合 integration，避免两条主线漂移。

示例仅供未来实施，前提是已有首次提交、integration 和契约，且已选择允许写入的 worktree 父目录：

```bash
git worktree add -b feat/adapter-chatgpt ../ferry-wt-chatgpt integration
git worktree add -b feat/migration-engine ../ferry-wt-engine integration
git worktree add -b feat/gui ../ferry-wt-gui integration
```

worktree 不复制未提交改动。不能让多个 AI 共用目录再切分支；worktree 隔离工作区/索引，却不能消除同文件修改的 Git 冲突。

建议合入次序：契约 -> CI/测试入口 -> 最小格式与核心 -> 首个平台 -> CLI/GUI 纵向链路 -> 其他平台小 PR -> 两机/安全门禁 -> 发布。核心与格式可交换，只要接口兼容；测试从第一天开始，不最后补建。

### 8. 冲突规避

| 冲突来源 | 约束 |
|---|---|
| 多平台改注册/别名 | 集成人独占；模块测试直接 import 平台文件 |
| 各自扩充 UCM/协议 | 版本冻结；缺字段先提公共契约 PR，不在各分支各造定义 |
| 多人修改公共帮助函数 | 先模块内小实现，确认多个调用者后由所属负责人集中提取 |
| 多人改 package/锁文件 | 只由集成人增依赖并刷新；模块提交需求和理由 |
| 测试集中大文件 | 各模块独有测试/样本目录，公共 harness 单独负责人 |
| 测试污染真实电脑 | 所有路径通过 env/临时 HOME 注入；真实产品测试另行显式授权 |
| GUI/核心接口漂移 | 同一契约 fixture、错误码、进度事件，变更同步消费者契约测试 |
| AI 越界修改 | 任务含允许/禁止目录；CI 检查 diff 白名单，公共变更单独审批 |
| 产物/端口/机器争抢 | 独立临时目录与端口；不提交缓存/真实导出；打包由发布负责人执行 |
| 应用或多个任务同时写同一存储 | 关闭目标应用或获得可验证锁；按资源锁定，不能安全锁定则拒绝写入 |

GitHub 可用 CODEOWNERS、受保护分支和合并队列，其他 Git 服务用等价机制。路径白名单只是补充，不替代评审。

### 9. 安全迁移与保真

**事务式流程，不伪称全局原子事务**

1. 获取源存储稳定快照；SQLite 用一致性备份/受控读取，不把正在写入的主文件直接当完整快照。
2. 校验归档；预检目标产品/schema、权限、磁盘、路径、项目和工具/附件。未知目标 schema 拒写，退为归档/交接。
3. 生成零写盘 ImportPlan，展示新增/冲突/保留/降级和完整写入路径。确认后应用，先重检旧状态摘要，防止预览后目标已变化。
4. 为资源加锁，先持久化恢复日志，备份待修改文件/索引/数据库的一致性状态；新建文件同样登记。
5. 暂存、校验后受控提交；DB 内用事务，跨文件/DB 用日志和补偿恢复，不承诺跨资源数据库式原子性。
6. 提交后重新读取并验证消息/索引/ID/附件关联；中断重启识别未完成任务，给恢复入口。
7. 回滚检查导入后的状态，遇到用户后来改动就停下或进入冲突恢复，不拿旧备份覆盖新会话。先列候选并确认，再移动待替换文件到隔离备份，不直接删除，同时生成一键还原脚本。

默认冲突策略：内容完全相同则跳过；同来源 ID 而内容不同要比较版本/分支，不按标题合并、不静默覆盖；关系不明保留双方、分配新目标 ID，并更新父子/工具/索引关联。

只重映射结构化工作区路径，不全局替换历史正文、代码或 URL。验证 Windows/macOS/Linux 的大小写、盘符、分隔符、UNC、Unicode 和同名目录；目标哈希目录按其规则重算。

**隐私与不可信输入**

- 历史只作为数据：不执行历史工具调用、不自动访问 URL、不把旧 system 文本提升为目标运行权限。提示注入也必须按不可信内容处理。
- 不打包 Cookie、浏览器 profile、授权令牌、SSH 私钥；目标重新授权。脱敏覆盖消息、元数据、文本附件、日志和可选原始内容，明确无法识别所有秘密。
- 默认本地。敏感归档使用标准认证加密和可靠 KDF，密码不进入日志、命令行历史和清单，不自行设计密码算法。
- 限制条目数、单文件/总体解压体积、压缩比、嵌套深度、KDF 资源消耗；拒绝绝对路径、路径穿越、危险符号链接和重复路径覆盖。
- 会话/附件逐项校验；普通哈希仅能检查意外损坏，不认证来源。密码错误、篡改、关键缺失显式失败，不能静默导入。
- GUI 按不可信文本渲染，禁止任意 HTML；本地 API 仅回环监听，验证 token、Origin/CSRF、上传体积、目标路径。
- 保留源端可用未知块；脱敏、截断、扁平化可追溯。源端缺失的数据不伪造。原始快照如需要，须显式选择并加密，仍不能绕开凭据排除和脱敏。
- 交接包按最近任务、已确认决策、待办与必要原文组织；超预算拆包或明确截断，原归档仍完整保留。AI 摘要可选、经确认、标来源，不替代事实记录。

### 10. 测试分层与发布门禁

| 层级 | 负责人 | 验收条件 |
|---|---|---|
| 单元/契约 | 模块作者 + 测试负责人 | 固定输入有确定输出，坏行/未知字段/错误版本显式处理，不写真实 HOME |
| 包格式/转换 | 格式作者，测试交叉评审 | UCM 往返、附件哈希、分支/工具关联、损失报告正确；密码错误/篡改失败 |
| 写入安全 | 核心作者 + 独立测试 | dry-run 文件树/DB 零变更，重复导入幂等，锁/路径/磁盘不足/中断/DB 失败/回滚保护通过 |
| 跨 OS/版本 | 测试分支 | 每个支持组合有样本和测试；范围之外降级，三种 OS 路径分别验证 |
| 真实续聊 | 平台作者提供复现，非作者复核 | 历史可见 -> 发消息得到回复 -> 关闭重启仍可继续，记录 OS/产品/扩展版本和模式 |
| 两台电脑 | 集成/测试 | A 导出 -> 传输 -> B 校验/导入 -> 目标继续，无需复制原路径或登录凭据 |
| GUI/CLI/发行 | GUI + 集成人，测试复核 | 同计划同结果；取消/错误可恢复；干净环境启动；API/渲染安全 |

用合成与人工脱敏的真实结构样本，覆盖空会话、中文/多语言、长消息、编辑分支、工具失败、缺失附件、损坏行和恶意包。用户原始对话、凭据、未授权截图不得入 Git。

性能测试使用合成数据。先保证可见进度、明确体积上限，不一次把无限历史读入内存；现有缓冲区实现未流式化前，设限并实测，不能提前声称支持任意大文件。实际瓶颈出现再加流式/并发。

CI 分层：路径相关测试 + 公共契约快速检查，合并队列跑受影响集成测试，发布跑完整矩阵。CPU/GPU 密集任务前查电源；本地未接电或状态未知不跑大矩阵，提供带电源闸门的脚本，重任务优先放在有电源保障的 CI。

### 11. 4 个 AI 分波次排期

| 阶段 | AI-A：协调/核心 | AI-B：格式/云端 | AI-C：本地平台 | AI-D：测试/界面 |
|---|---|---|---|
| 契约准备 | 负责契约和文件归属 | 评审包格式/转换需求 | 提交本地真实格式需求 | 设计契约用例和 GUI fixture |
| 第一波 | 最小核心/CLI、安全写入、集成时段 | 包格式/交接，随后 ChatGPT | Claude Code 读取及限定目标计划 | 先测试入口，再 mock GUI |
| 第二波 | 联调首条链路、恢复/回滚 | Claude 网页导出、国内能力探测 | Cursor 读取，写入另设门禁 | GUI 接真接口、执行 E2E |
| 第三波 | 认领独立平台任务、集成发布 | 通义/文心/DeepSeek 分任务推进 | Copilot、Cursor 限定版续聊 | 两机、跨 OS、安全回归 |

14 个职责不需 14 个常驻 AI。同一 AI 可先后领多个分支，但每次仅写自己的范围；转交先提交并说明未完成项，再移交 worktree。4 AI 下由协调者保留固定集成时段，不必另设一个只合并的常驻 AI。评审由非作者承担。

**里程碑**

- M0：契约/样本/所有权冻结，各分支能独立测试。参考准备时间 0.5-1.5 个工作日，不含获取样本的等待。
- M1：ChatGPT/Claude 网页的用户导出包 -> UCM -> 加密归档 -> B 机查看/交接，先交确定价值。
- M2：一个明确版本本地目标，优先已有原型的 Claude Code，完成预演/备份/续聊/重启/回滚，只声明已测过的来源与内容组合。
- M3：Cursor、Copilot 分读/写阶段扩展，国内网页按真实入口接入。没有原生回写仍可发布归档/交接。
- M4：扩大版本/OS，之后再评估打包体验、增量归档、性能；不先建设云账户代管、实时双向同步或插件市场。

假设原型可用、样本齐全、4 AI 与必要人工验收可用，首条链路可按约 1-2 周试排，不是工期保证。闭源格式调查、账号权限、真实两机验证最不确定，M0 后依据样本重新估算。

**提速机制与衡量**

- 转换实现从 N×M 收敛为 N 个读取器 + M 个目标计划生成器，兼容性测试仍逐实际路径确认。
- 契约/mock 让核心、平台、GUI、黑盒用例同期推进，小样本先走完整链路。
- 能力探测、读取、计划、真实续聊分小 PR；调查失败不阻塞其他平台。
- 小 PR 当日评审，及早暴露分歧；复用 env、Blob、加密、损失报告、harness，不把平台差异塞进公共大文件。
- 限并发，重测试串行或上 CI，避免争抢数据库、磁盘和内存。
- 跟踪 PR 等待、冲突率、回归失败率、平台从开工到验收时间，不按 AI 数量宣称线性提速。

估算示例：若 75% 工作可并行，4 路理论上限为 `1 / (0.25 + 0.75 / 4) = 2.29` 倍，尚未扣评审、联调、硬件竞争和真实产品验收。这是假设示例，不是本项目实测。

### A.1 基线测试：22/22 通过，但只在 Node 24 上

```text
Node v24.18.1  node --test --test-isolation=none test/core.test.js test/adapters.test.js
→ tests 22 / pass 22 / fail 0 / 1397ms
```

原型是可用的，M0 不需要从零验证。

但换成 Node 22.22.2：

```text
node.exe: bad option: --test-isolation=none
```

`--test-isolation=none` 是 Node 24 才有的参数，而 `package.json` 声明 `engines.node >= 22.5.0`。
**声明与脚本不一致**，且 `npm test` 是这个项目唯一的验证入口。首次提交前必须二选一：

- 收紧 `engines` 到 `>=24`（推荐，改动最小，且 Node 24 已是当前 LTS 线）；
- 或去掉该 flag，同时确认测试间的状态隔离仍成立（`test/helpers.js` 用 `.tmp/tests` 共享目录，去掉隔离后可能出现相互污染）。

### A.2 首次提交的阻塞项：`.gitignore` 覆盖不全

`git symbolic-ref --short HEAD` = `master`，`git log` 无提交，未跟踪项 13 个。与 §1 一致。

但当前 `.gitignore` 只覆盖 `.tmp/`、`dist/`、`node_modules/`、`*.ferrypack`、`ferry-handoff/`、`ferry-converted/`，
**没有覆盖 `.idea/` 与 `.workbuddy/`**。13 个未跟踪项里这两项会被 `git add .` 直接带进首次提交：

```text
?? .idea/          IDE 工程配置，含本机绝对路径
?? .workbuddy/     工作区记忆与本地状态
```

§7 第 1 条说"不直接执行 `git add .`"是对的，但只靠人工纪律不如直接补 ignore 规则可靠。
首次提交前需补：`.idea/`、`.workbuddy/`（顺带确认 `.vscode/`、`*.log`、`*.tmp` 是否需要）。

### A.3 §4"针对当前代码，先拆必要的冲突热点"——三条属实，两条要修

| 上文判断 | 实测 | 处理 |
|---|---|---|
| `web-exports.js` 混合 ChatGPT / Claude / 通用格式 | 属实，但实际含 **4 个** importer：`chatgpt-export`、`claude-export`、`generic-json`、`markdown` | 拆成 4 个文件，不是 3 个 |
| `ucm.js` 混合模型、渲染、交接、脱敏 | 属实。`createConversation/validateConversation/conversationStats` + `renderMarkdown/renderHandoff/estimateTokens` + `redactText/redactConversation` + `conversationFingerprint/contentHash` 全在一个 464 行文件里 | 按"模型 / 渲染 / 脱敏 / 身份"四块拆，`contentHash` 属于身份，不要跟着渲染走 |
| 文件导入器"沿用 `detect(buf, filename)`" | **属实**（本条为上一稿误判，已更正）。`src/core/registry.js` 的 `pickImporter()` 调用 `imp.detect?.(buf, filename)`，`web-exports.js` 里 4 个 importer 各自实现了 `detect`。`extractConversations()` 是共用辅助函数，不是入口 | 契约沿用即可。但 `defineImporter()` 只给了 `extensions` 默认值，没有要求 `detect` 必填 —— 契约应把 `detect` 提升为必需项，否则新 importer 漏写会静默匹配失败 |

### A.4 被低估的最大工作量：`import()` 现在是"边算边写"

§4 把 `planImport(...)` 写成"已验证可写目标新增"。实际情况是：`src/core/migrate.js` 直接调用
`store.import(env, conv, { dryRun })`，**每个适配器自己在写函数内部判断 `dryRun` 来决定是否落盘**。
也就是说"计划"和"执行"在同一次遍历里纠缠，不存在可以单独产出、单独审阅的零写盘计划。

要满足 §9 第 3 条"生成零写盘 ImportPlan → 确认后应用 → 应用前重检旧状态摘要"，
必须把**每一个适配器的 `import()` 拆成 `planImport()` + `apply()` 两段**。

这是全项目唯一一处真正的破坏性重构，涉及 10 个适配器，而不是 1 个。

**由此暴露一个边界漏洞**：§5 规定 `migration-engine` 独占迁移核心，`adapter-*` 独占各自适配文件。
但 `planImport` 的**接口**在核心、**实现在各适配器**，两边必须同时改才能跑通一条链路——
这恰好是 §3 想避免的耦合并发。修法建议：

1. 契约分支先把 `planImport` 的返回结构（ImportPlan）**只定义、不实现**，并给 1 个已适配的参考实现（选 Claude Code，因为原型已有原生写入）；
2. `migration-engine` 提供 `planImport` 的**默认包装器**：适配器若未实现，包装器用现有 `import()` 的 `dryRun` 模式反推计划并标注 `fidelity: 'inferred'`；
3. 各适配器在自己的分支里逐步替换为真实两段式，替换前链路可用、只是计划精度低。

这样任何单条适配器分支都能独立跑通、独立验收，不必等待其他适配器一起重构。

### A.5 生产期风险提示

`test/helpers.js` 把 `.tmp/tests` 固定在 `process.cwd()` 下，`makeEnv()` 伪装 HOME。
这一层是对的。但**没有真实 HOME 的保护性断言**——如果某个适配器将来绕过 `env` 直接读 `os.homedir()`，
测试不会报警，只会在开发者真机上读到真实会话。建议契约测试加一条：
运行期间用 monkey-patch 让 `os.homedir()` / `process.env.HOME` 指向蜜罐目录，任何真实读取即失败。
